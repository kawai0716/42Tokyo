# Pipe Execution Fix - 2025-07-05

## 問題の概要
コミット `cb66a67` (pass norm, but break) でのリファクタリング後、パイプコマンドが正しく動作しなくなった。特に以下のような複数パイプのコマンドが失敗していた：
- `env | sort | grep -v SHLVL | grep -v ^_`
- `cat ./test_files/infile_big | grep oi`
- パイプとリダイレクションを組み合わせたコマンド

## 根本原因
リファクタリング時に導入された `ex_pipeline.c` に以下の問題があった：

1. **デッドロック問題**: `create_second_child` 関数で、第2子プロセスが第1子プロセスの終了を待ってから実行を開始していた
   ```c
   if (pid2 == 0)
   {
       close(fd[1]);
       waitpid(pid1, NULL, 0);  // これが原因でデッドロック
       pipeline_child(fd, fd[0], cmd);
   }
   ```

2. **不正なロジック**: `pipeline_child` 関数が同じコマンドノードを両方の子プロセスで使用しようとしていた

## 解決策
オリジナルの実装に近い形に修正：

1. **第2子プロセスの待機を削除**: パイプの両端が並行して動作するように修正

2. **直接的な実行に変更**: 
   - 第1子プロセス: 標準出力をパイプにリダイレクトして左側のコマンドを実行
   - 第2子プロセス: 標準入力をパイプから読み込んで右側のコマンドを実行

3. **不要な関数の削除**: `handle_left_pipe`, `handle_right_pipe`, `pipeline_child` を削除

## 修正後のコード
```c
int create_first_child(int fd[2], t_node *cmd)
{
    pid_t pid1;
    
    pid1 = fork();
    if (pid1 == -1) {
        // エラーハンドリング
    }
    if (pid1 == 0) {
        close(fd[0]);
        dup2(fd[1], STDOUT_FILENO);
        close(fd[1]);
        execute_node(cmd->u_data.pipe.left);
        exit(g_exit_status);
    }
    return (pid1);
}

int create_second_child(int fd[2], t_node *cmd, pid_t pid1)
{
    pid_t pid2;
    
    pid2 = fork();
    if (pid2 == -1) {
        // エラーハンドリング
    }
    if (pid2 == 0) {
        close(fd[1]);
        dup2(fd[0], STDIN_FILENO);
        close(fd[0]);
        ex_main(cmd->u_data.pipe.right);
        exit(g_exit_status);
    }
    return (pid2);
}
```

## テスト結果
修正後、以下のコマンドが正常に動作するようになった：
- `ls | grep Make` → Makefileのみ表示
- `env | sort | grep USER` → USERのみ表示
- `env | sort | grep -v SHLVL | grep -v ^_` → 複数パイプも正常動作
- `cat file | grep pattern` → ファイル入力も正常

パイプテストの結果: 47/60 合格（改善）
