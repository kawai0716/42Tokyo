### 🔍 失敗テスト分析

#### 1. Test 61: 空コマンド処理
**現象**: mini exit code = 0, bash exit code = 127
**問題**: 空文字列コマンドの終了コード不一致
**解決方針**:
```c
// src/executor/pipe.c の run_simple_cmd で空コマンド検出
if (!cmd->u_data.cmd.argv[0] || !cmd->u_data.cmd.argv[0][0])
{
    g_exit_status = 127;  // bashと同じ動作
    return;
}
```

#### 2. Test 64: リダイレクション構文エラー
**現象**: mini exit code = 2, bash exit code = 127
**問題**: 特定のリダイレクション構文での終了コード不一致
**解決方針**:
- パーサーでの構文エラー検出を精密化
- bash互換の終了コード調整

#### 3. その他のエッジケース（推定）
以下の問題が残存していると推定されます：

##### 3.1 特殊文字処理
**問題**: 制御文字や非印字文字を含む入力の処理
**解決方針**:
```c
// レキサーでの文字検証強化
int is_valid_char(char c)
{
    return (c >= 32 && c <= 126) || c == '\t' || c == '\n';
}
```

##### 3.2 複雑なクォート組み合わせ
**問題**: ネストしたクォートや特殊なエスケープシーケンス
**解決方針**:
- クォート処理ステートマシンの強化
- bashの動作を厳密に模倣

##### 3.3 環境変数展開の境界ケース
**問題**: 特殊な変数名や未定義変数の処理
**解決方針**:
```c
// 変数名検証の強化
int is_valid_var_name(const char *name)
{
    if (!name || !*name || (!ft_isalpha(*name) && *name != '_'))
        return (0);
    while (*++name)
        if (!ft_isalnum(*name) && *name != '_')
            return (0);
    return (1);
}
```

##### 3.4 ファイル操作エラー処理
**問題**: 権限エラーやファイル不存在時の細かい終了コード
**解決方針**:
- errno を活用した詳細なエラー分類
- bash と同一の終了コード設定

##### 3.5 シグナル処理の境界ケース
**問題**: 特殊なシグナル状況での終了コード
**解決方針**:
```c
// シグナルハンドラーでの終了コード設定
void sigint_handler(int sig)
{
    (void)sig;
    if (g_shell_mode == MODE_HEREDOC)
        g_exit_status = 130;
    // その他のモード対応
}
```
